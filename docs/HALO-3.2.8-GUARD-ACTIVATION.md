# HaloTV 3.2.8 桌面守护与权限修复测试

内部号：Standard / Guard 232，Lite 88。保持独立版包名、签名、启动图；包含上一轮 231 / 87 的全链路性能调整。本次仅交付本地测试包，不发布、发公告或操作电视/模拟器。

## 已修改的调用链

- 控制中心「设为主屏幕」加入一键开启与修复。主动点击后记录恢复意愿，在已有权限范围内修复失效注册、恢复自有组件、请求守护及通知连接。操作单飞；受限设置、无障碍、通知使用权、悬浮窗、使用情况访问、电池优化、厂商自启动、默认桌面分项引导。系统页面返回后重新读取状态，授权步骤保存在 ViewModel，不因控制中心离开前台释放而丢失。
- 没有 WRITE_SECURE_SETTINGS 时显示「等待授权」与电脑配置说明，不能把恢复意愿开关当成获得权限。系统缺少入口时明确提示，不声称自动授权成功。没有引入应用内 ADB、后台 shell 或第三方授权工具。
- 通知状态区分实际授权与实际连接。Android 8.1+ 通过 NotificationManager 查询当前安装组件的授权，不再单靠 secure 字符串；较旧系统读取准确的组件。保留其他通知监听；低内存 Android 10 及以下的系统限制单独提示。
- 通知监听增加断开状态清理、限频重连请求，以及屏幕唤醒事件恢复。不会读取通知内容。请求重连不等于获得授权。
- 修复 GuardBootWatch 把绑定宽限期/冷却期内的无操作也计为修复的问题。仅实际重新启用或发起重绑才消耗次数。普通回调不能延长窗口；开机、解锁、升级、真实唤醒或主动修复可以开启一轮有限窗口，最多 5 分钟、3 次实际修复。原有其他入口仍受重绑单飞、5 秒绑定宽限及 15 秒冷却约束。
- 保留主动关闭自动恢复、待机退出、厂商关机保护及其他无障碍服务。只清理已经确认卸载的旧包失效注册或本包错误类名；不卸载旧版/Aerial、不自动关闭其他守护、不改用户信号源。
- Lite 不包含完整版 HomeGuardService。新增真实能力说明与默认桌面、系统应用管理入口及厂商后台权限指引，继续兼容 Android 4.x；不显示虚假的守护开启状态。

## 仍须用户确认的边界

普通 APK 无法自行获得 WRITE_SECURE_SETTINGS、替所有厂商设置 AppOps 或强制成为默认桌面。需要电视系统页面确认；入口被隐藏时使用电脑安装指南/已有 tools/halo-guard.sh 的明确修复模式。只有授权且系统实际绑定后才显示运行。自动授权不是一个可跨所有电视承诺的能力。

厂商自启动、关联启动、后台保活没有统一公开查询/授权 API，界面将其标为需系统确认；不是写成功就显示全部开启。其他应用竞争提示保留，交由用户在系统里选择，不盲目停用。Android 官方通知授权参考：https://developer.android.com/reference/android/app/NotificationManager#isNotificationListenerAccessGranted(android.content.ComponentName)

## 验证范围

新增主机回归覆盖：通知列表保留与独立身份、现代系统授权真值、无权限/主动退出、低内存限制、引导拒绝不循环、绑定宽限不耗次数、开机窗口之后的唤醒恢复、监听连接/销毁状态，以及唤醒恢复不启动第三方应用。完整测试、构建与 APK 校验结果见桌面 verification.json。

本机编译/单元测试不能替代厂商电视实测。没有证明所有电视不再掉守护，也没有测得本轮帧率或内存的真实改善。

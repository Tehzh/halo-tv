# HaloTV 3.2.8 动态壁纸交接测试包

本地测试交付：Standard/Guard 内部号 233，Lite 内部号 89。沿用独立版包名、签名及启动图，保留上一版守护权限和性能修改；没有发布、操作电视或运行模拟器。

## 代码中确认的问题与修改

- 本地视频的“空闲后播放”在返回桌面时重新等候 10 秒。首次进入仍尊重空闲设置，已经出过画面的视频返回时直接恢复，后续真实按键仍遵守空闲模式。
- 启动独立视频屏保时只主动释放在线壁纸解码器，没有同样交接本地视频。现在两条路径均先显示原生过渡遮罩，再暂停/停止解码；重复交接不会重复停机。
- 照片、必应图片、时钟和翻页时钟屏保不需要另一个视频解码器。桌面主动启动这些屏保时保留窗口及暂停的壁纸画面，退出直接续播；真正离开 Activity 仍停止解码，不在其他应用后持续播放。
- 指定同一本地视频作为壁纸和单选屏保时复用播放器。不同视频、多个视频轮播与单选不匹配的情况仍分开，避免屏保播放错误内容。
- 原生遮罩等首帧提交并经过两个显示帧后做 140ms 淡出；新一轮遮盖使旧回调失效，重复首帧回调不重复发起动画。
- 离开在线动态桌面时读取现有 TextureView 的小尺寸过渡画面，取消离开路径上的网络/软件解码兜底；本地视频的 PixelCopy 同样限制到至多 640×360。慢设备不继续反复尝试昂贵复制，文件/磨玻璃处理不阻挡解码器交接。
- 在线壁纸首次开始播放的缓冲阈值降为 250ms，再缓冲为 1s；保持原有缓存容量和电视 HDMI/解码保护。屏保独立播放器的缓冲参数不变。

以上动态壁纸逻辑属于 Standard/Guard；Lite 本次同步打包及内部号，保留之前的权限与性能修复，没有新增完整视频引擎。

## 验证范围与边界

新增回归覆盖：已有画面返回与冷启动区别、单选屏保与播放列表匹配、删除文件后的匹配、两种播放器交接入口、遮罩重复回调。三版单元测试、Release 构建、Lint 和 APK 身份/签名/对齐校验结果随桌面包提供。

这不是电视实测结果：厂商合成器、HDR/杜比视界显示模式切换、存储及网络速度仍可能影响恢复。降低初始缓冲在慢网络下可能更早进入再缓冲，需要实际试播反馈。小尺寸复制只用于短暂交接，不改变正常视频播放分辨率。照片/时钟屏保期间会保留一个暂停的视频解码器，耗用少量额外资源；不同视频及其他应用仍释放解码器。没有承诺所有电视绝对零闪屏。

建议实机检查：本地及在线视频分别进行桌面→屏保→桌面、桌面→其他视频应用→桌面；连续快速切换数次，并测试“空闲后播放”、单视频屏保、不同视频屏保和照片/时钟屏保。留意是否有黑帧、超过数秒的停顿、错误播放列表或异常内存增长。

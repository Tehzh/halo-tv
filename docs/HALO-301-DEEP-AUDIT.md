# HaloTV 3.0.1 三版本复核记录

检查日期：2026-11-11。基线是已经整合 Aerial 1.94、加入远程公告的本地版本，提交 `9138ddd`。

本轮交付仍显示 **3.0.1**，正式版内部号由 179 提高到 **180**，Lite 由 37 提高到 **38**。沿用原包名及签名，可覆盖同包名、同签名且内部号更低的版本。Guard 和 Standard 是同一包名的两种构建，只安装其中一个；Lite 独立升级。

## 检查方法和边界

- 对三个 Release 分别重新编译、混淆、资源收缩、打包及静态检查；第一轮基线和修复后的全量验证均禁用构建缓存并重新执行任务。
- 执行现有及新增的单元、Robolectric、Compose 回归测试，覆盖桌面导航、壁纸和屏保交接、更新、公告、守护及部分厂商适配。Robolectric 是电脑上的安卓代码测试环境，不是电视实机。
- 检查 APK 清单、最低系统版本、ZIP 完整性、v1/v2 签名、签名一致性和安装包对齐；Lite 检查单 dex。
- 编译检查手机端内嵌脚本和 `halo.js`；检查五种语言公告资源及 Lite 构建时共享源码的同步方式。
- 运行安装、恢复和 TCL 传输脚本的离线回归测试。全部设备连接与下载在这些测试中均为替身，没有实际操作电视。

**本轮没有安装到电视、没有打开模拟器、没有发布 GitHub 或官网，也没有获取新的实机帧率、CPU、PSS 或耗电数据。** 通过代码和自动测试不等于已验证所有电视的解码器、遥控器和固件。本轮没有承诺“所有页面零卡顿”或“完全没有 Bug”。

## 已修复：安装包中的代码

### 1. Lite 公告长文不能完整阅读

原实现将一整段正文当作一个无限增高的卡片。遥控焦点进入时，外层滚动容器可能直接对齐卡片底部；如果公告是一整段很长的文字，中间内容难以逐行读完。

改为高度受限的正文阅读区：方向键上/下先翻阅正文，到达首尾后才继续移向其他按钮。翻页之间保留少量重叠，避免漏读。只在宽度变化时重新排文字，不增加计时器或空闲动画。新增长文、短文和整张公告页的遥控导航测试。

正式版与 Lite 的公告标题同时限制为两行，超长部分省略显示，避免标题把正文和操作按钮挤出可用区域；正文保留完整内容。

### 2. 公告说明链接的路径校验不够严格

原来的 GitHub 链接校验只检查仓库路径前缀，包含 `..` 的地址可能在浏览器规范化后跳出项目路径。

现在拒绝点路径、编码后的点路径和反斜杠路径。仍只允许预先认可的 HTTPS 官网或本项目 GitHub 链接，不接受任意外部地址。共享策略和三个版本的回归用例一起更新。

### 3. Lite 在旧安卓上下载成功仍可能无法打开安装器

原实现对 Android 7 以下发送 `file://` 地址，但文件位于私有缓存。旧系统安装器直接按路径读取，可能无法访问，表现为无法解析或安装失败。

现在保留私有待安装文件及原有校验，安装前为旧系统准备一份位于本应用外部缓存中的只读交接文件。只替换同一固定文件，不累积多个更新包；没有可用外部缓存时返回失败，不开放整个私有目录。Android 7 及以上继续使用带临时只读授权的 ContentProvider。仅 Android 4.0–4.3 声明旧系统访问自有外部缓存所需的存储权限，现代系统不申请这项权限。

仍校验同包名、同签名、更高内部版本及适用版本，不允许借此推送任意软件。新增旧安卓文件交接、缓存不可用、现代 content URI 三个回归测试。旧电视实际安装仍需确认。

### 4. Lite 翻页时钟在低高度画布上可能崩溃

字体大小的原上下限在高度低于约 474 像素时会倒置，导致范围参数异常。

修正为始终有效的字号范围，覆盖 320×180、720×400、800×480、960×540、1280×720 的绘制测试。并复用绘制用的矩形、字体度量及数字字符串，减少翻页期间反复创建的小对象。没有删掉翻页动画或改变正常电视上的字号设计。这是分配路径优化，不是实测帧率提升数据。

## 已修复：仓库辅助工具

以下改动位于 `tools/`，**不会打进 APK，不会自行在用户电视上执行**。

1. 本地构建失败时立即停止，避免继续安装上一次遗留的旧文件。
2. 下载先写临时文件，确认传输成功、ZIP 完整且包含清单与主 dex 后才替换目标文件。网页、空文件、损坏或截断的下载不再当作 APK 使用；失败时保留原文件。
3. 即使 ADB 进程返回成功码，只要没有明确的安装成功结果，也停止后续授权步骤；签名冲突给出明确原因，不自动卸载应用或清除数据。
4. TCL 连接检测区分 macOS 和其他系统的超时参数。
5. 恢复配置时，如果系统不支持通知监听撤销命令，使用兼容路径仅移除本应用的监听项，保留其他服务。
6. TCL 传输解析拒绝负数和过大的数据长度，避免死循环或无限缓冲；识别系统拒绝安装的阶段，及时返回失败；所有退出路径关闭连接。

这些是上游保留的辅助脚本，部分默认仓库、下载地址、包名和文案仍面向 Aerial。**本轮没有把它们作为 HaloTV 用户安装教程或公开安装入口发布**，不要直接把脚本默认下载结果当作本次 HaloTV APK。今后若要发布脚本，应另行完整整理默认下载源与设备授权流程。

## 性能与体积原则

- 不新增常驻清理服务、后台推送服务、持续刷新界面或全屏实时模糊。
- Lite 新增的 Robolectric / AndroidX 测试依赖仅用于电脑回归，**不进入发布包**；Lite 继续不依赖 Compose，最低 Android 4.0，单 dex。
- 大部分静态检查的 `StaticFieldLeak` 提示来自保存 applicationContext 的应用级缓存；已核对关键初始化与退出清理路径，没有仅为消除提示而拆掉必要缓存。
- 已核对自定义 TLS 信任实现：仍有证书校验和针对旧系统的兼容逻辑，没有改成信任全部证书。
- Lint 仍有历史 API、厂商反射、代码风格和资源建议，不能把“0 Error/Fatal”说成“0 告警”。不批量删除看似未使用的厂商入口和兼容资源，以免造成其他电视回归。
- 安装包精确字节数、签名、SHA-256、自动测试和静态检查结果以同文件夹的 `安装包信息.json`、`检查记录/` 为准。

## 尚需实机验证

本次电脑检查没有发现测试覆盖范围内尚未解决的失败，但没有覆盖所有组合。建议在正式公开发布前，至少验证：

1. 本地动态视频反复进入控制中心、退出应用、进入/退出屏保，尤其是只有一个硬件解码器的电视。
2. 完全关机重启、待机唤醒与长时间使用后的 Home 守护，以及固件是否收回权限。
3. Android 4.x/5.x/6.x 上的 Lite 更新安装，真实遥控器阅读长公告、按返回键和确认按钮。
4. 官网真实下发公告/撤回、弱网更新失败回退、大文件上传、儿童模式的悬浮答题。

未进行以上实机验证的项目不标为“已完成”。也没有自动提高输出分辨率、强制刷新率或改动用户电视系统设置。

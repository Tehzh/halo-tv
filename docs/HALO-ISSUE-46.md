# Issue 46：在线静态壁纸切换后仍显示旧图

范围：修复 bug，不新增产品功能。基于 `7614a3f`，保留 Dock 大小和信息对齐、独立包名/签名、Logo、欢迎页、已有设置和性能处理。显示版本 3.3.4；Standard / Guard 内部号 249，Lite 105。本轮仅桌面测试包，不发布、不操作电视或模拟器、不修改 Issue。

## 根因与证据

公开报告：https://github.com/Null9797/halo-tv/issues/46 。报告未提供版本、类型或机型，不能断言用户命中了哪条路径。

- 正式版 `Wallpapers.replaceBingCached` 复用 `photo:bingrotation` 并替换同名文件，随后 `select` → `setSelection` 在 ID 相同时直接返回，后台桌面/磨砂位图不重建。启动时会重新读取文件，符合“重启才更换”的表现。
- 正式版和 Lite 的烘焙 key 依赖文件时间戳；快速同名替换、低精度文件时间戳会产生内容变了而缓存 key 没变的问题。
- 原手动请求在下载结束后才检查选择状态，可能漏掉切走又切回相同 ID；并行手机请求也缺少起始意图顺序。Lite 原先在线图片在工作线程直接覆盖文件，然后主线程才检查页面是否仍有效，可能出现文件已替换但刷新回调被丢弃。

## 修改

- 正式版成功提交在线图后增加内容版本，失效缩略图并强制重建同 ID 桌面；增加选择/渲染世代，继续拦截旧解码与旧写盘回调。原有效桌面在新图准备好前保留。
- 两个实现的烘焙 key 都加入持久化在线内容修订号，不依赖文件时间戳单独识别新内容。在线图仍是私有可替换缓存，不写入用户照片。
- 先失效旧缩略图，再公开内容修订号，避免手机拿新版本 URL 时仍命中尚未清除的旧缩略图。
- 请求在网络开始前记录意图顺序及选择世代；新手动请求淘汰旧请求，切走再切回来不能复活旧请求。自动轮换等待进行中的手动选择，并保留原有轮换配置检查。
- 图像验证/编码先写临时文件，最终有效性检查后才发布。Lite 将发布移至主线程检查之后；失败或取消时删除临时文件，保留原图。
- 桌面、手机入口和自动轮换使用对应的同一提交路径；手机手动选择同步更新轮换目标。手机缩略图 URL 使用内容版本，避免浏览器沿用同 ID 的旧图；桌面预览缓存也识别已更换的背景对象。

## 本轮验证

专项测试使用本机生成的纯色图片及 Android 原生图像解码/绘制，不依赖在线图片服务。覆盖 A→B 的桌面/磨砂/缩略图、固定时间戳、连续替换、乱序完成、坏图、暂存写失败、取消已暂存请求、处理中切换类型、切走又切回、实际轮换提交 API 及过期轮换。

对照试验只临时恢复同 ID 短路（`refresh = false`），实际流水线测试按预期在旧/新背景对象仍相同处失败，证明测试可捕获原问题；随后恢复修复。该失败是故意的负向对照，不是尚未修好的测试失败。

最终完整测试、Lint、三版本构建、包名/签名/资源和安装包检查，以桌面 `VERIFICATION.json` 和构建日志为准，不能沿用上一轮 Dock 测试数量。电视/模拟器、用户机型、真实网络条件及厂商解码/合成行为未在本轮验证。

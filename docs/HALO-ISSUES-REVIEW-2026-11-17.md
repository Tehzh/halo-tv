## 本轮修复：在线壁纸重试可能持续为空

关联 [#32](https://github.com/Null9797/halo-tv/issues/32)，但不足以认定该用户的具体原因已解决。

- 原共享目录缓存把合法 JSON 的空数组当作有效成功缓存，六小时内点击重试仍会命中它；格式正确但所有行不可显示也有类似问题。
- 目录下载成功后，缓存写失败会使整个请求失败，即使已经获得可显示数据；直接写目标文件还可能留下截断缓存。
- 分页总数在过滤无效缩略图之前计算，会出现总数不为零、当前页却为空；重复日期还会产生重复 Compose 网格 key。

现在统一在缓存、计数和网格前验证目录：仅保留合法日期与既有受限缩略图路径，并按日期去重。空目录不缓存；空 / 截断 / 无效缓存会重新请求。写入使用本应用缓存目录中的临时文件再替换，写失败仍返回已验证的网络结果，不删除原缓存；未来时间戳也不会被无限视为新鲜。正式版图库沿用已有失败 / 重试提示，不新增选项。相同共享实现进入 Lite，不增加依赖、主机或协议许可。

复审时主机网络实际返回 3,909 条有效、互不重复的目录记录，约 1.11MB，符合现有 schema 与 4MB 上限；这仅证明该时刻主机可访问，不能证明反馈电视的 DNS、TLS、地区线路或服务端始终正常。因此 #32 仍需用户端验证，保持开放。

新增回归覆盖空缓存重试、截断缓存、写失败、失败后保留原缓存、无效目录不落盘、正常缓存不重复请求、过滤前后分页及重复 key、系统时钟校正。测试使用合成目录和受控文件系统失败，不请求真实网络、不修改主机权限。
